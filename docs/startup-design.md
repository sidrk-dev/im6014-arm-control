# Startup verification design

Base: Gemini's separate verifier and thin offline driver. Preserve existing production and test files. Graft Sol's actual-main event-loop verification, recording rejection sentinels, callback failure propagation, clean thread shutdown, and receipt-after-success ordering.

Reject Gemini's arbitrary image-byte threshold and screenshot mtime as proof. Use exclusive fresh evidence paths, current pixmap capture/hash/dimensions, and parent visual inspection. The standalone CLI also transmits packets; the audit includes it. Reject modifying the existing large test script solely to add startup behavior. The driver runs byte-identical copies of trusted source/tests in disposable storage because the old tests intentionally write files relative to their source directory.

Usage: `scripts/check_offline_baseline.sh [absolute-python] [evidence-root]` produces a fresh run. It captures subprocess logs and executes existing packet/UI tests plus `test_startup.py --source real|demo --evidence-dir ...`. Startup verifier calls actual `motor_dashboard.main()` with real application arguments, wraps Dashboard construction, and schedules a callback after normal timer updates. Serial constructors, demo constructor, and exchange are sentinels that record and reject attempts. Patch port enumeration for deterministic no-device display. Callback exceptions are recorded, close normally, and fail the process. Before and after close verify bus None, disconnected/disarmed, zero TX/RX, no exchange/open attempts, worker active then terminated, and GUI timer active then stopped. Reject zero-window/zero-event-loop false positives and nonzero application exit. Capture a non-null rendered screenshot; write result only after successful shutdown. No claims about connected hardware. Negative harness probes must demonstrate attempts and invalid lifecycle produce failure.

State shape: startup JSON with source mode, application argv, Python/package/source fingerprint, observed pre/post state, sentinel counts, and screenshot path/hash/size. Milestone TSV is the durable record, not runtime application state. No framework or new production abstraction.

Rubric: safety isolation, production preservation, repeatable evidence, minimal code, clear boundaries. Two terminal candidates received; no substitutions. Independent Muse recommendation recorded in evidence. Parent checks every artifact and screenshot.
