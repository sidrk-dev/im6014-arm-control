# Coordination

The coordinator owns integration, Git, physical I/O, review triage and delivery. Workers use separate worktrees and assigned file scopes; all agents are peers for technical judgment. Record the base revision and an honest handoff with changed files, hashes, commands actually run, failures and requested parent checks.

The arm dashboard is the user's current priority. C07–C16 and assembled-arm station work are paused. The single-J1 release is based on accepted main; do not import the unfinished multijoint controller backlog to deliver it. J2/J3 are virtual. The current live motor authorization covers only the secured, unloaded ID0 J1 and bounded low-speed movement.

An incoming Opus collaborator should inspect current Git state and the task registry, choose an independent scope, and contact the coordinator before editing shared files or using hardware. A branch name or prior invitation does not establish that a job is currently writing. Never overwrite another actor's changes. Close dependent writers before changing their required parent HEAD.

Use Pstack poteto-mode for nontrivial work, route assigned roles from the frozen run sheet, and retain terminal receipts/dropouts without invented retries. Prefer simple working controls and targeted outcome checks over repeated broad test loops. Apply accepted review findings to the source, not merely the documentation. See `docs/development/hardware-debug-reference.md` for physical bus topology, Channel D (ttyUSB3) routing, and driver troubleshooting.
