# Coordination

The coordinator owns integration, Git, physical I/O, review triage and delivery. Workers use separate worktrees and assigned file scopes; all agents are peers for technical judgment. Record the base revision and an honest handoff with changed files, hashes, commands actually run, failures and requested parent checks.

The user resumed the controller milestones after the U2D2 software commit 4d41d5b. C07-C10 are developed on codex/controller-c07-c10, with one core writer and a parent-run check before each next milestone. The transport-free core is separate from the browser and bench control paths. Production station integration remains pending. This run uses fake transport and performs no physical motor I/O. Replacement-adapter wiring inspection and actual Stop/status verification remain physical commissioning gates.

An incoming Opus collaborator should inspect current Git state and the task registry, choose an independent scope, and contact the coordinator before editing shared files or using hardware. A branch name or prior invitation does not establish that a job is currently writing. Never overwrite another actor's changes. Close dependent writers before changing their required parent HEAD.

Use Pstack poteto-mode for nontrivial work, route assigned roles from the frozen run sheet, and retain terminal receipts/dropouts without invented retries. Prefer simple working controls and targeted outcome checks over repeated broad test loops. Apply accepted review findings to the source, not merely the documentation. The adapter selector defaults to the shared U2D2 profile. See `docs/u2d2.md` for its inspection and communication limits; the old FT4232H mapping in `docs/development/hardware-debug-reference.md` is historical.
