# Connect and verify a U2D2

This guide covers the ROBOTIS U2D2 and a Unitree IM6014. Physical U2D2 testing is pending. Complete the cable inspection and communication check below before moving a motor.

## Select the U2D2 profile

1. Start the dashboard while disconnected.
2. Select **U2D2** under **Adapter profile** and select **Refresh**.
3. Select the serial path that matches the adapter and cable you inspected. If more than one FT232H-class candidate appears, choose the one connected to the motor. The dashboard leaves the default path blank when the candidate count is zero or greater than one.
4. Use the serial path from the current list. The U2D2 serial number and by-id name are not known before the board arrives.

The registry marks a device as an FT232H-class candidate only when available USB metadata agrees with VID `0403`, PID `6014`, and interface `0`. This is a candidate classification. It does not prove that ROBOTIS made the board or that the cable reaches the motor. A product name alone does not identify a candidate.

The bench CLI uses the same profiles. Run `python3 spin_5rpm.py --list-ports` to view the passive list. The command does not need `--arm` and does not open a serial port. For a later bench run, pass `--adapter-profile u2d2` and an inspected `--port`. The CLI may omit `--port` only when exactly one U2D2 candidate is listed. It stops before log creation if the candidate is missing or ambiguous.

## Inspect the cable before power

Keep the motor's 36 V supply off and disconnect USB while you inspect the cable. Verify the actual connector pinout, continuity, polarity, and isolation before connecting anything.

The U2D2 four-pin RS-485 connector is expected to use `GND`, `NC`, `D+`, and `D−` in that order. Leave `NC` disconnected. Match `D+` and `D−` to the verified motor cable polarity. Connect the common reference only after you confirm the pinout. Keep 36 V off every U2D2 signal pin.

ROBOTIS describes the U2D2 connectors and USB latency guidance in its [U2D2 documentation](https://docs.robotis.com/docs/parts/interface/u2d2/). Inspect the supplied cable yourself. A matching connector shape does not prove its pinout.

## Set and read back the Linux latency value

ROBOTIS recommends a 1 ms USB serial latency value for this use. This setting is a manual operator step. It does not persist across device removal or reboot, and this workbench does not change it.

Resolve the selected by-id path to the current tty:

```sh
read -r -p 'Paste the selected serial path: ' u2d2_port
readlink -f -- "$u2d2_port"
```

Use the returned `/dev/ttyUSBn` name in the exact FTDI driver attribute below. Read the current value, set it to `1`, then read it back:

```sh
cat /sys/bus/usb-serial/devices/ttyUSBn/latency_timer
echo 1 | sudo tee /sys/bus/usb-serial/devices/ttyUSBn/latency_timer
cat /sys/bus/usb-serial/devices/ttyUSBn/latency_timer
```

Replace `ttyUSBn` with the tty resolved from the selected, present by-id alias. Do not guess the device number. Do not add a udev rule or run automatic sysfs tuning.

## Verify communication before motion

After the cable inspection, connect USB and apply motor power only to the verified motor power pins. Select **6 Mbps** and the correct motor ID. The IM6014 link uses raw Unitree frames at 6 Mbps and 8N1. Do not use `DYNAMIXEL PacketHandler` for this motor.

Connect sends Stop/status. Require repeated CRC-valid Stop/status replies at 6 Mbps on the actual motor and cable before any bounded motion or compatibility claim. A visible candidate, a successful serial open, or a product label does not establish motor communication.

The old FT4232H adapter's serial and interface measurements remain historical evidence for that adapter. They are not U2D2 results. The U2D2 remains unverified until it arrives and passes the electrical inspection and communication gate above.

## Software validation (2026-10-13)

The adapter changes passed 106 focused Python tests, eight JavaScript tests across five files, and all nine offline baseline groups. These checks used fake transports and isolated PTYs. Both bench startup captures showed U2D2 selected with zero serial opens or exchanges.

The browser check verified adapter-profile selection and Connect → Enable → Stop → Disconnect with the simulated three-joint profile. The white-and-black dashboard and CAD preview were visually inspected. This check did not establish physical U2D2 communication or motor movement.

The Muse source review was triaged and a fresh independent Sol review found no remaining source blocker. MiMo's review failed with HTTP 502 and produced no findings; it remains a review dropout.
