## 1. Code findings

### [Medium] Startup receipt fingerprint is incomplete - tampered test files would not be detected
Location: `test_startup.py:_fingerprint`, `scripts/check_offline_baseline.sh:files=(...)`

Execution path:
- Driver copies 8 files byte-identical to scratch: `motor_dashboard.py motor_session.py spin_5rpm.py test_spin_5rpm.py test_dashboard.py test_startup.py test_startup_verifier.py USER_MANUAL.md`, then `cmp -s` and `cd scratch` and runs tests there.
- Receipt `source_fingerprint` only records 6: `motor_dashboard.py motor_session.py spin_5rpm.py USER_MANUAL.md test_startup.py test_startup_verifier.py`.
- Missing: `test_dashboard.py`, `test_spin_5rpm.py`.

Evidence: `evidence/baseline/startup/startup-real/startup-result.json:source_fingerprint` has 6 keys; driver `files` array has 8.

Impact: Receipt proves which production files ran, but not which packet/UI test files ran. A mutated `test_dashboard.py` in scratch would still produce a passing receipt with identical fingerprint.

Suggestion: Add the two missing test files to `_fingerprint`. Keep the 6 existing entries byte-identical. One-line fix, no behavior change.

### [Medium] Verifier records interpreter/packages but never enforces them
Location: `test_startup.py:validate_report`, `test_startup.py:run:report{python,packages}`

Execution path:
- `run()` captures `sys.version`, `PySide6`, `pyserial` versions into report.
- `validate_report()` checks `system_exit, exit_code, argv_restored, window, callback, pre/post, sentinel_counts, screenshot` - never checks `python.version` or `packages`.
- `scripts/check_offline_baseline.sh` accepts any `[absolute-python]`, only logs `python-version.txt`, never asserts `3.12.14`.

Evidence: `startup-real/startup-result.json:python.version 3.12.14` is present but no validator asserts it; driver `run_logged` would PASS with system `3.14.6` if Qt/pyserial happened to import.

This does not invalidate the current parent run - `clean-environment.json`, `parent-verification.json`, and both startup receipts all show `3.12.14` - but the guard itself cannot catch a wrong-interpreter run.

Suggestion: Either assert in `validate_report` that `python.version` starts with `3.12.14` and `packages` match `requirements.lock`, or explicitly document that version-pinning is a parent-inspection step outside the JSON gate. Do not silently rely on CI `python-version: '3.12.14'` alone, since the script is also runnable locally.

### [Low] Fragile line-continuation in negative harness
Location: `test_startup_verifier.py:test_faults_fail_actual_startup_process:script`

`with patch.object(motor_dashboard, "Dashboard", FaultyDashboard), \` inside a `'''...'''` string relies on backslash-newline handling inside triple-quoted strings to collapse to a single `with A, B:` line. It works today - 7 injected faults pass, 5 verifier tests pass - but it is needlessly brittle and hard to read.

Suggestion: Use parenthesized `with (patch... , patch...):` or two nested `with` statements in the generated script. No behavior change, removes a future syntax break.
